# AeroShield 电子系统 · 双脑架构 v0

> 本文是电子层的总览:角色分工、数据流、供电拓扑。引脚细节见 `schematics/pin-map.md`,选型见 `schematics/bom-phase2.md`,脑间协议见 `firmware/protocol.md`。
> 建立于 2026-10-11,对应 ADR 0002(储物羽人电混合驱动)。

---

## 1. 两个脑,两种性格

```
ESP32-S3「感知脑」                        ESP32「动作脑」
装在腰骶背板内侧(贴人体侧)               装在上背翼舱(v06 外壳内)
──────────────────────                  ──────────────────────
多传感器采样 + 滤波 + 阈值判定            状态机 + 动作库(Phase 1 资产)
对外无线(BLE 手机 / WiFi 调参台)          舵机/风扇实时驱动(20ms 环)
Phase 3 头寸:步态/姿态 tinyML            20Hz 状态帧 ← UART ← 感知脑
```

**分工铁律:阈值和迟滞放在信号源头(S3),动作策略放在时序源头(ESP32)。**

为什么双脑(虽然一颗 ESP32 也勉强够装下 Phase 2):

1. **失败隔离**:舵机堵转把 5V 轨拽出 brownout 复位动作脑时,感知无感;反之 WiFi/BLE 栈重启也不闪舵机;
2. **互为看门狗**:UART 静默 500ms → 动作脑进安全态(IDLE + 呼吸微动);ESP32 掉线 → S3 BLE 告警;
3. **功耗分治**:S3 深睡 + 定期唤醒的常时感知是 mA 级,舵机轨按需上电——双脑比单脑全天省电;
4. **Phase 3 头寸**:步态相位/姿态分类需要 PSRAM 与向量指令,只有 S3 跑得动。

## 2. 中翼执行器与传感器总账(一对)

| 载荷 | 数量 | 型号级 | 驱动 | 备注 |
|---|---|---|---|---|
| 翼根展收 | 2 | MG90S 级 | LEDC PWM | 表达力主轴;前后俯仰走凸轮耦合(被动,零执行器) |
| 挂钩保持杆 | 2 | 微型舵机(2.5–5g 级) | LEDC PWM | 凸轮压紧/释放 4 根弹簧挂钩,兼复锁(ADR 0002) |
| 背部散热风扇 | 1–2 | 5V 无刷小风扇 | MOSFET + PWM | 温湿度超阈触发,SHT40 喂的 |
| 接近/挥手 | 1 | APDS-9960 | I2C(动作脑) | 中翼背板上缘居中;触发挂钩弹出 |
| 羽闭合确认 | 8 | 微动开关(静态背板) | GPIO | 每羽 1 个;v2 可换电容检测复用触摸通道 |
| 储物羽开羽 | 0 | — | **人手** | 经挂钩 + 二级机械行程(README §6.2) |

舵机合计 **4 个/对**,不是 6,更不是 12。

## 3. 感知脑传感器(全 I2C 一条总线,地址零冲突)

| 元件 | 型号 | 位置 | 喂给系统的状态 | 地址 |
|---|---|---|---|---|
| IMU | MPU6050(升 ICM-42688) | S3 板上,腰骶,X 轴沿脊柱 | 躯干姿态、微蹲、远期步态 | 0x68 |
| 心率血氧 | MAX30102 | 肩带/腰带内侧 | 运动强度、紧张度 | 0x57 |
| 温湿度 | SHT40 ×2 | 背板贴身 1 + 中翼外 1 | 背部闷热 → 散热触发 | 0x44 |
| 接近 | VL53L1X ToF | 上背肩部,朝前外 | 有人靠近 → 展翼问候 | 0x29 |
| 电量计 | MAX17048 | 电池端 | 续航管理 | 0x36 |

肌电明确不进本轮(电极与信号链是 Phase 3 的事)。GPIO 只用 ~7 个,S3 大量富余。

## 4. 自动控制管线

```
S3:采样(IMU 100Hz / PPG 25Hz / 温湿 1Hz / ToF 10Hz)
   → 滤波(滑窗 + 姿态卡尔曼)
   → 阈值 + 迟滞就地判定
   → 10–20Hz 紧凑状态帧 {state, conf, hr, temp…} + CRC
   → UART 115200 ↓
ESP32:状态机(Phase 1 三层架构原封不动,喂状态的从板载 IMU 换成 S3)
   → 动作映射(pose-matrix 的固件化身)
   → 关键帧队列 + 缓动插值 → 舵机/风扇
```

降级链路双向:UART 静默 500ms → 动作脑回 IDLE + 呼吸微动,绝不僵死;动作脑掉线 → S3 BLE 告警。

调参闭环:**S3 出一个 servo_web 同款网页控制台**(WiFi 直连看 IMU/心率/温度实时曲线,阈值在浏览器里拖),和舵机台一脉相承。

## 5. 供电拓扑

```
电池(Phase 1 沿用 1S 103450 桌面调试;Phase 2 电池构型待定,倾向 2S)
 ├─ 5V 大电流轨(3A 同步降压):舵机 ×4 + 风扇 ×2
 │    每侧舵机电源端 470–1000μF;分路供电、共地铁律不变
 └─ 3.3V 逻辑轨(LDO):S3 + 全部传感器 + 两块 ESP32
      S3 深睡常时感知 <1mA 级
```

Phase 1 的 MT3608(2A 上限)只用于桌面调试;Phase 2 上 3A 同步降压模块(2S 时用 buck,1S 时用同步 boost)。电池构型是开放问题,拍板时进 ADR 0003(供电架构)。

## 6. 与现有代码的关系

- `firmware/servo_test/`、`firmware/servo_web/` 继续作为舵机调试台(单舵机),不受本架构影响;
- Phase 1 的三层固件(传感层→状态机→动作层)是动作脑的骨架,S3 接入后只替换传感层的数据来源;
- 状态位定义见 `firmware/protocol.md`,与 `docs/pose-matrix.md` 一一对应。
