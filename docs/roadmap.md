**关键观察（决定目录设计的三个事实）：**

1. **迭代速度极快**：v03→v06 在一天内完成，"方案被推翻重来"是常态（README §19 也明示了这一点）→ 版本归档必须是零成本惯例，不是偶尔的整理。
2. **Phase 1 的验收产物是一支演示短片**（README §15）→ 媒体资产（渲染、照片、视频）从第一天起就要有固定去处，不能散落在桌面。
3. **建模尚未真正开始**（Fusion 未装）→ cad/ 是接下来的主战场，导出规范要先立好，避免每次 AI 建模会话临时决定文件去向。

## 3. 命名与版本规范

### 3.1 打印件（stl/）

- 命名：`v<两位版本号>_<部件组>_<部件名>.stl`，如 `v06_shell_top.stl`（沿用现有惯例）
- 迭代中的部件带版本号；每次结构迭代 +1；被取代的旧版本**原文件名不改**移入 `stl/archive/`
- 稳定不变的基础件（羽毛、门钩）可不带版本号
- 若将来部件多到平铺看不清，再按翼区加前缀：`w1_`（上层）/ `w2_`（中层）/ `w3_`（下层），当前不必

### 3.2 CAD 源文件（cad/）

- `.f3d` 命名：`aeroshield_<部件组>_v<NN>.f3d`，与 STL 版本号对齐
- 每个里程碑同时导出 STEP 到 `cad/step/`（中性格式，Fusion 源损坏时还能救回几何）
- Fusion MCP 默认导出到桌面，**每次会话结束必须把导出件挪入对应目录**，桌面不留产物

### 3.3 文档（docs/）

- 文件名小写连字符：`pose-matrix.md`、`2026-08-30-首次试打印.md`
- README 是根源文档：**只修订设计思想**（为什么存在、与人体什么关系）；工程结论（尺寸、材料、机构参数）进 `docs/decisions/` 或 `docs/journal/`

### 3.4 决策记录（docs/decisions/）

- 命名：`0001-<短标题>.md`，序号递增不复用；模板见 `TEMPLATE.md`
- 触发条件：任何"以后可能被问为什么"的选择——锁止角度、传动级数、材料、传感器选型
- 底线：决策必须与根源原则对齐（减负 / 机械优先 / 功能分区），冲突时写明理由

## 4. 阶段路线与产物去向（对齐 README §15）

### Phase 0：工具链就绪（当前所处阶段）

- [ ] 安装 Fusion 360 本体（清华镜像；注意 MCP Add-In 版本约束 <2），加载 Add-In 验证 MCP 连通
- [ ] 本目录结构 + .gitignore + 现行 STL 提交入库（首个结构性提交）
- [ ] 确认本机是否存有 v03–v06 的 .f3d 源文件：有则入库，无则列入重建任务
- [ ] 重建参数化源文件：以 v06 外壳/舱门 + 羽毛 + 门钩为对象，在 Fusion 中建首个参数化模型 → `cad/fusion/`

### Phase 1：第一原型 —— 1/6 上层主翼（2026-09 → 2027-02，半年落地）

> 详细技术依据见 [decisions/0001](decisions/0001-机电一体电子参与动作.md)：电机给主驱动（每侧 1 舵机），机械给动作质感（级联/回位），传感器+状态机触发。机电一体共行，无纯机械阶段。
>
> **周级执行参照：[phase1-execution.md](phase1-execution.md)**（物料清单、公差参数、四杆/槽机构设计值、每周交付物与风险表；参数表为实测后回填的活文档）。
>
> **协作分工（按用户能力画像：电子熟手 / 机械新手）**：电子与固件（供电、堵转保护、数据采集）由用户主导，agent 平级协作；机械设计与 Fusion 建模由 agent 教学式代劳（M1–M2 全代建、M3 起移交参数修改、M4 目标独立建简单件）；agent 另负责机构方案对比与运转视频诊断。
>
> **用户学习主线（机械速成四层）**：① 打印公差手感（M1，公差试条起步）→ ② 机构最小集：自由度/四杆/死点/槽机构（M2）→ ③ 机电匹配：扭矩链、堵转保护、舵机反馈闭环（M2–M3）→ ④ 装配设计（M3–M4）。

- 总目标：**1/6 人偶背上的一对上层主翼，能自己感知、自己做动作，拍成 90 秒 demo 短片**
- 技术栈：ESP32 + MG90S ×2 + MPU6050 + 光敏（超声可选），复用 v06 外壳/羽毛 STL
- 逐月里程碑：

| 月份 | 里程碑 | 验收标准 |
|---|---|---|
| M1 (9月) | 机电流水线一周打通（ESP32+舵机+IMU 触发，电子部分压缩为一周内）→ 公差试条建手感 → **首个四杆机构**驱动翼根弧线展开（agent 代建 Fusion） | 一片翼沿弧线轨迹自动展开，且能说清四杆的主/连/摇杆 |
| M2 (10月) | 机构高考月：缓动曲线 + 羽毛级联（**槽机构主攻**，拉簧备选）+ 四杆轨迹迭代；每轮打印做参数阵列（4–6 变体/轮），预计 5–8 轮 | 旁观者说"像翅膀"；逐帧对照猛禽展开视频 |
| M3 (11月) | 左右成对 + 背板集成，动作库 5–6 个；**轨迹数据闭环**（舵机反馈曲线 vs 设计曲线调参，用户主导） | 脱离面包板独立运行 |
| M4 (12月) | 上人偶：重心配重、电池供电、30 分钟稳定运行 | 朋友靠近自动展翼打招呼 |
| M5 (1月) | 拍 4 场景成片：靠近/遮阳/收拢/呼吸感；文档补全 | 90 秒成片 |
| M6 (2月) | 缓冲打磨 + README v0.2 + 发布 | MVP 交付 |

- 时间预算：约 170 小时（每周 6–8h）——机械/打印装配 ~55%、代码 ~15%、电子 ~5%、拍摄剪辑 ~15%、文档 ~10%；M2 是最大风险池，缓冲优先给它
- 砍单纪律：超期两周即冻结迭代、带当前版本进入下一阶段；永不砍"自动开合 + 感知触发"两项
- 明确不做（防蔓延）：中层/下层翼、遥控 App、遮雨演示、多自由度翼
- 产物去向：
  - 建模 → `cad/fusion/`；中性格式 → `cad/step/`；打印件 → `stl/`（旧版随手入 `stl/archive/`）
  - 固件 → `electronics/firmware/`（M1 起即启用）；接线 → `electronics/schematics/`
  - 试装与动作验证 → `media/photos/`；渲染 → `media/renders/`；成片 → `media/video/`
  - 机构选择理由 → `docs/decisions/`；进展 → `docs/journal/`

### Phase 2：六翼完整版

- 新增验证：中层磁吸挂载 / 储物 / 背部散热；下层姿态识别 / 机械锁止 / 悬空支撑 / 负重转移
- 产物去向新增：传感器与控制 → `electronics/`；锁止机构等关键决策 → `docs/decisions/`
- 力学传导分析（`docs/force-line.md`）在此阶段必须给出第一版完整结论

### Phase 3：研究型增强

- 步态识别、被动储能、代谢实验（README §15 Phase 3）
- 产物去向新增：实验数据与协议届时在 `research/` 下增设 `experiments/`（现在不建，避免空转）

## 5. 工作流约定（每轮迭代固定节奏）

1. **建模**：Fusion 会话内完成一个部件组的完整迭代
2. **导出三件套**：`.f3d` → `cad/fusion/`；里程碑加导 STEP → `cad/step/`；打印件 → `stl/`
3. **归档**：被取代的 STL 原名移入 `stl/archive/`；被推翻的源文件移入 `cad/archive/`
4. **留痕**：关键取舍写 `docs/decisions/`；当日进展写 `docs/journal/`；矩阵与分析文档同步修订
5. **提交**：一轮迭代一个 commit，信息格式 `v06: shell/door 舱门铰链修改` 这类"版本 + 一句话"

## 6. 维护规则

- 本文档在**目录结构或规范变更时**更新，日常进展不写这里（写 journal）
- 新增顶层目录前先问：它对应 README 的哪个阶段/哪类产物？答不上来就不加
- 归档永远不删除：STL 和源文件都很小（当前共 ~2.6 MB），历史是设计依据，git + archive 双保险
